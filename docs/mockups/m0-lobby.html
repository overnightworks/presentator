Presentator Lobby

The lobby in the family look: appkit’s tokens and fonts, presentator’s teal in the app slot (#0c6c77 on #ffffff in light, #56c3cd on #06181b in dark). Every board is drawn once and shown at 1280 px and at 390 px; the theme follows the device until you choose.

Page theme

States: shape and colour

readya filled disc — deck ready, source reachable, voice active
buildingan open ring, turning only while work runs — building, downloading, loading
faileda triangle — only a person can end this
never fetcheda dashed square — has not happened yet, not downloaded
Downloadeda split disc — installed, not the one in use

Deliberately left out

  • No theme icon in the bar — theme lives in the person menu; presenter and projector views use Slidev's own d key for dark mode
  • OAuth, GitHub App, host picker — one read-only secret per source, the same form for every host (#8 line 1)
  • Writing back to Git — the server is a mirror, never the origin (#8 line 1)
  • Showing the secret again — after entry it can only be renewed (#8 line 12)
  • New deck / upload — decks are created in Git (#8 line 4)
  • Name filter — twenty decks don't need one (#8 line 18)
  • Sign up, forgot password, local accounts — Keycloak owns sign-in and accounts; presentator has no first-start page, login form, Users tab, password change, or session list (K13, #242)
  • Start in M0 — the two views are the way into the talk; the co-presenter run arrives with M1 (#8 line 10)
  • Build progress bar — the server doesn't know percentages
  • Marketplace, arbitrary Hugging Face IDs, cloud voices, voice cloning — five fixed candidates only, admin-picked (picture blessed 10.09.2026; V1–V9 adopted; candidates remain unintegrated)
